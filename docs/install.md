# Installation

## Requirements

- Linux `amd64` is the primary supported platform.
- Linux `arm64` is supported when Docker images are available for the host.
- Docker Engine with a running daemon.
- Docker Compose v2.
- Python 3.11 or newer.
- `/dev/net/tun` on Linux.
- A Proton VPN WireGuard configuration file generated by the user from Proton,
  or Proton OpenVPN/IKEv2 credentials for OpenVPN TCP/443 mode.

Docker Desktop on macOS or Windows is best effort and not a security target for
the first release.

## Install

```sh
git clone https://github.com/drplagash/ProtonBrowserBox.git
cd ProtonBrowserBox
./setup.sh
```

`setup.sh` checks requirements, configures the selected protocol, and starts the
appliance. It reuses settings when they already exist. Use `./install.sh` for
installation only, without configuring or starting the VPN.

## First Configuration

Choose one VPN mode.

### WireGuard import

```sh
cp ~/Downloads/proton.conf config/vpn/wireguard/
./vpn-browser config
```

Put downloaded Proton WireGuard `.conf` files in `config/vpn/wireguard/`. If
there is exactly one `.conf` file there, the wizard imports it automatically. If
there are multiple `.conf` files, the wizard asks which one to use. The wizard
fixes local file permissions automatically before reading the selected file.

It imports only the WireGuard private key into:

```text
config/vpn/secrets/wireguard_private_key
```

The full `.conf` file is not copied into project configuration. The project
launcher stores runtime configuration under `config/vpn/`, which is ignored by
Git because it can contain secrets and browser profile data.

Non-secret WireGuard peer metadata from the `.conf` file, such as endpoint IP,
endpoint port, public key, and interface address, may be stored in settings. When
those fields are present, the appliance uses Gluetun's custom WireGuard provider
mode to connect to that exact Proton endpoint. The private key still stays in
the secret file above.

### OpenVPN TCP/443

Use Proton OpenVPN over TCP/443 when WireGuard UDP does not pass the current
network. This asks for Proton OpenVPN/IKEv2 credentials, not the normal Proton
login password:

```sh
./vpn-browser server --openvpn-tcp
```

If no previous configuration exists, this command creates default local
settings and stores the OpenVPN credentials as private files under
`config/vpn/secrets/`.

To choose RAM, profile persistence, web port, and resolution too, run:

```sh
./vpn-browser config --openvpn-tcp
```

Find the manual OpenVPN credentials at
[account.protonvpn.com/account](https://account.protonvpn.com/account), under
**Account -> OpenVPN username** (also labeled **OpenVPN / IKEv2** in some
interfaces). See [Proton's official instructions](https://protonvpn.com/support/vpn-login).
The account login email and password are different from these credentials.

## Start

```sh
./vpn-browser
```

When the VPN becomes healthy and the browser is ready, open:

```text
http://127.0.0.1:5800
```

If the VPN repeatedly reports healthcheck TLS handshake timeouts, the browser is
not started and the kill switch remains closed. Regenerate the Proton WireGuard
configuration, try another Free server, or test whether outbound UDP/51820 is
blocked on the current network.

## Server Selection

Use Proton Free automatic selection:

```sh
./vpn-browser server --auto
```

Limit Proton Free selection to a country supported by Gluetun:

```sh
./vpn-browser server --country "United States"
```

Return to the exact imported WireGuard peer, when the original `.conf` included
complete peer metadata:

```sh
./vpn-browser server --exact
```

Use Proton OpenVPN over TCP/443:

```sh
./vpn-browser server --openvpn-tcp
```

Restart the appliance after changing the server selection.
